# Taste Lens verification

## Result

The canonical perceptual Lens model is now version 2 and supports `taste/judgment` as an inspectable purpose/profile. It remains the same Lens object and is never treated as an executable action.

- Focused shared tests: 8/8 passed.
- Focused runtime effects: 6/6 passed (5 app/director, 1 extension).
- Runtime screenshots cover resolve/create, explicit teaching, before/after proposal, inspection, and materialized evaluation.
- Extension handoff preserves explicit-selection scope, disables full-page collection, and marks examples private.

## Tested behavior

- “I hate filler words” becomes a confirmed negative principle with quoted-speech and intentional-rhythm exceptions.
- “Looks AI generated” becomes six editable observable anti-pattern suggestions and an explicit no-detector caveat.
- Persistent updates require explicit save/remember intent and return an undo receipt.
- Run-specific preserve constraints compile into the judgment envelope without mutating the saved Lens.
- Before/after pairs create review-only diffs with private artifact refs.
- Evaluation returns evidence and materializes linked feedback while recommending a separate preserve-original revision Function.
- Lens merge reports possible preference conflicts.
- Default export excludes paired examples, critiques, candidate feedback, and other private raw evidence.

## Evidence boundary

The browser audit used production-shaped local state and real director/extension handlers. It did not perform a live model inference for before/after facets; that path is contract-tested and remains provider-dependent. Screenshots prove UI/runtime reachability, not subjective agreement with an inferred preference.
