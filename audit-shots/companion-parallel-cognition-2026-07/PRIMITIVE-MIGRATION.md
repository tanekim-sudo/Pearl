# Primitive Move redundancy and migration

## Canonical set

1. **Branch** — creates an adjustable, branch-specific candidate set.
2. **Deepen** — exposes underlying mechanisms, assumptions, and principles.
3. **Challenge** — attacks weaknesses and tests the opposition case.
4. **Merge** — synthesizes two or more Materials while preserving sources.
5. **Embody** — makes an abstraction concrete through examples.

This is the smallest coherent starting set. Research, Compress, Reframe, and other useful transforms remain ordinary editable Moves; they are not discarded.

## Migration aliases

| Legacy meaning | Canonical Primitive Move |
|---|---|
| Expand, Explore | Branch |
| Combine, Synthesize | Merge |
| Decompose, underlying principles | Deepen |
| Invert, Critique, Counterexample | Challenge |
| Ground, Concretize | Embody |

Migration resolves names through aliases while preserving a user's edited definition, stable override, and ordering preference. It does not create duplicate cards. Primitive defaults remain editable, versioned, promotable/demotable, reorderable, and sorted ahead of ordinary Moves and Functions.

Merge proximity is screen-space based: 72 px arm, 96 px hysteresis release, and 420 ms dwell. Dropping while armed creates a new Merge result; source nodes remain intact and the normal workspace checkpoint supports undo.
